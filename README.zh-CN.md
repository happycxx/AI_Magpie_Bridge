## 📌 项目简介

**AI 鹊桥（AI Magpie Bridge）** 是一个连接对话式 AI 与本地代码文件的桌面端安全替换工具。

它不让 AI 直接操作你的文件系统，而是让 AI 输出明确、可审查的代码替换块，再由本地工具执行精确匹配与替换。

它适合搭配 **ChatGPT、Claude、Gemini** 等先进对话式 AI 使用，用于将 AI 生成的代码修改快速、安全地应用到本地文件。

传统流程通常是：

> 复制代码给 AI → AI 返回修改建议 → 手动查找 → 手动替换 → 手动保存

使用本工具后，可以变成：

> AI 输出标准替换块 → 工具自动解析 → 一键应用到本地文件 → 自动保存

本项目的核心目标是让 AI 辅助编程变得 **更安全、更高效、更省钱、更可控**。

## 🔥 为什么需要这个工具

AI 鹊桥的核心安全边界是：**AI 只输出文本，不能直接读写你的本地文件；本地工具只执行明确、可审查、可匹配的替换块。**

现在很多 AI Coding Agent 很强，但在实际使用中也存在一些明显问题。

### 1. 传统 Agent 的黑箱操作太大

很多 Agent 会直接读取、修改、创建、删除项目文件。

用户往往只能在操作完成后才知道它到底改了什么。  
一个很小的自然语言需求，可能触发一长串隐藏操作：

> 扫描项目 → 读取多个文件 → 生成计划 → 修改文件 → 运行命令 → 再次修改 → 再次验证

这些过程虽然自动化程度高，但也带来了明显的不确定性：

- 它可能修改与你需求无关的文件
- 它可能重构过多代码
- 它可能覆盖你不希望修改的内容
- 它可能误删文件
- 它可能把错误修改扩散到多个位置

本工具采用完全不同的方式：

> 你提供上下文 → AI 明确输出替换块 → 工具只执行精确匹配的替换

AI 无法直接操作你的文件，所有修改都是显式可见的。

---

### 2. 自然语言 Agent 工作流非常消耗 token

传统 Agent 往往需要大量上下文和多轮工具调用。

有时候你只是想修改一个很小的地方，但 Agent 可能会：

- 反复读取文件
- 生成长计划
- 多次调用工具
- 自动验证
- 失败后重新尝试
- 不断扩大上下文范围

结果就是：

- 一个小修改也可能消耗大量 token
- 使用 API 时可能花费数美元甚至数十美元
- 使用订阅制工具时也会迅速消耗次数或额度
- 等待时间可能从几秒变成十几分钟甚至更久

而使用本工具时，你可以把关键代码直接提供给最先进的对话式 AI。  
AI 一次回复就能按你的逻辑生成大量高质量代码修改。

很多情况下：

> 只消耗一次对话次数，就能获得完整修改方案。

这对钱包非常友好，也极大减少等待时间。

---

### 3. 对话式 AI 本身已经足够强

现在最先进的对话式 AI，在给到足够代码上下文后，已经可以：

- 理解业务逻辑
- 按你的要求修改代码
- 一次生成大量补丁
- 遵守指定格式输出
- 给出更接近你意图的实现

相比让 Agent 自己在项目中探索，不如你直接把关键文件、关键函数、项目结构发给 AI，让它基于明确上下文输出替换块。

本工具负责最后一步：

> 把 AI 生成的修改安全、快速、准确地应用到本地文件。

这是一种更透明的 “人控 AI” 工作流。

---

### 4. 防止不可信平台夹带私活

一些低价或不可信的 AI Agent 平台，如果拥有项目文件操作权限，理论上可能带来额外风险：

- 在代码中夹带无关逻辑
- 修改配置文件
- 读取不该读取的文件
- 插入难以发现的隐藏行为
- 删除或覆盖重要文件

本工具不会让 AI 或第三方平台直接接触你的本地文件系统。

AI 只能输出文本。  
工具只会根据明确的替换块进行本地精确匹配替换。

这可以显著降低：

- 恶意修改风险
- 文件误删风险
- 隐藏变更风险
- 不相关文件被修改的风险

---

### 5. 颠覆式节省成本与时间

对于大量日常编程任务，这个工具的性价比非常高：

- 小修改不再需要启动昂贵 Agent
- 大修改可以让对话式 AI 一次性生成多个替换块
- 无需反复扫描整个项目
- 无需多轮工具调用
- 无需等待 Agent 长时间执行
- 无需承担黑箱自动操作风险

一句话总结：

> **它把对话式 AI 的强大代码能力，和本地精确替换的安全性结合起来。**

## ✨ 核心功能

- **多标签代码编辑器**
  - 支持同时打开多个文件
  - 支持行号显示
  - 内置 One Dark 风格 Python 语法高亮

- **AI 替换块解析与应用**
  - 支持 `<<<< 查找 ... ==== ... >>>> 替换` 格式
  - 支持一次处理多个替换块
  - 支持跨文件替换
  - 支持删除代码：替换内容为空即可

- **剪贴板自动监听**
  - 开启后，复制 AI 回复即可自动识别替换块
  - 命中唯一代码片段时自动替换并保存
  - 对格式错误、未命中、多处命中等情况自动跳过，避免误改

- **失败反馈一键生成**
  - 自动整理失败原因
  - 附带当前完整代码
  - 一键复制给 AI，让 AI 重新生成可应用的替换块

- **省钱的 AI 编程工作流**
  - 避免 Agent 反复读取文件和多轮工具调用
  - 只把必要上下文发给 AI，减少 token 消耗
  - 让对话式 AI 一次生成大量可应用代码修改
  - 小修改也能快速完成，避免高额 API / Agent 成本

- **比黑箱 Agent 更安全**
  - AI 没有直接写入项目文件的权限
  - 只有旧代码精确匹配时才会替换
  - 多处命中时自动跳过，避免误改
  - 降低隐藏修改、文件误删、不相关文件被改的风险

- **关键版本管理**
  - 支持手动保存关键版本
  - 支持版本对比
  - 支持加载历史版本
  - 支持删除无用版本

- **项目结构复制**
  - 一键复制当前项目目录结构
  - 帮助 AI 理解项目上下文
  - 多文件修改时更容易生成准确路径

- **响应式桌面 UI**
  - 窗口缩窄时自动进入紧凑模式
  - 按钮、输入框、操作区自动适配布局

- **状态持久化**
  - 自动恢复上次窗口位置
  - 自动恢复上次打开的标签页
  - 自动记录最近文件
  - 支持多语言界面

## 🧭 适用场景

这个工具特别适合：

- 经常让 AI 帮你修改 Python 代码
- 不想手动复制、查找、替换大量代码
- 想降低 AI Agent 的 token 消耗和使用成本
- 希望 AI 输出的修改可以被稳定应用
- 不希望 AI 或第三方平台直接操作本地文件
- 想防止 Agent 误删文件、误改文件、乱改项目
- 需要保存关键版本，方便回退
- 偏好透明、可控的桌面端工作流，而不是黑箱 IDE Agent

## 🎬 完整使用示例

下面演示一个完整流程：使用 AI 生成一个 PySide6 桌面时钟，并通过 AI 鹊桥自动应用到本地文件。

### 1. 先告诉 AI 输出固定替换块格式

在和 ChatGPT、Claude、Gemini 等对话式 AI 沟通前，建议先把固定提示词发给 AI，让它严格按照 AI 鹊桥支持的替换块格式输出。

![给 AI 的替换块提示词](docs/images/prompt-template.png)

这样 AI 后续返回的代码就会尽量符合：

```text
<<<< 文件: path/to/file.py
<<<< 查找
旧代码
====
新代码
>>>> 替换
```

---

### 2. 新建文件并拖入 AI 鹊桥

先在本地创建目标文件，例如：

```text
clock.py
```

然后将文件拖入 AI 鹊桥，或者通过左侧 **添加文件 / 项目** 打开。

![拖入文件到 AI 鹊桥](docs/images/drag-file-into-app.png)

---

### 3. 开启自动监听

点击顶部的 **自动监听：开**。

开启后，你只需要复制 AI 返回的替换块，AI 鹊桥就会自动检测剪贴板内容。

![开启自动监听](docs/images/operation-1-enable-listener.png)

自动监听模式下，工具会尽量自动完成：

```text
复制 AI 回复 → 检测替换块 → 精确匹配 → 替换代码 → 保存文件
```

如果格式不完整、旧代码未命中或命中多处，工具会自动跳过，避免误改。

---

### 4. 让 AI 生成第一个可运行版本

例如向 AI 提出需求：

```text
帮我写一个简单的 PySide6 UI 时钟，要求有现代极简风格。
```

AI 返回标准替换块后，点击复制。

![AI 生成第一个版本](docs/images/operation-2-auto-created.png)

AI 鹊桥检测到剪贴板中的替换块后，会自动将代码写入 `clock.py`。

---

### 5. 本地文件自动更新

替换成功后，代码会直接出现在本地文件中，并自动保存。

![代码已自动写入本地文件](docs/images/operation-3-code-applied.png)

这一步不需要 AI 直接操作你的文件系统。  
AI 只输出文本，真正的文件替换由本地 AI 鹊桥完成。

---

### 6. 继续让 AI 增强功能

你可以继续自然语言描述新需求，例如：

```text
给时钟添加右键菜单，支持 12/24 小时制切换、秒数显示开关和退出功能。
```

AI 会继续返回多个替换块。

![继续让 AI 增强功能](docs/images/operation-4-ask-ai-to-improve.png)

---

### 7. 再次自动替换成功

复制 AI 返回内容后，AI 鹊桥会继续自动应用修改。

![再次替换成功](docs/images/operation-5-final-result.png)

最终流程是：

```text
自然语言描述需求
↓
AI 生成替换块
↓
AI 鹊桥自动应用
↓
本地代码更新并保存
```

整个过程不需要 Agent 直接读写文件，也不需要手动查找和粘贴代码。

## 🧾 替换块格式

### 单文件替换

```text
<<<< 查找
原代码
====
新代码
>>>> 替换
```

### 多文件替换

```text
<<<< 文件: app/main_window.py
<<<< 查找
原代码 A
====
新代码 A
>>>> 替换
<<<< 文件: core/replace_engine.py
<<<< 查找
原代码 B
====
新代码 B
>>>> 替换
```

### 删除代码

当 `====` 下方为空时，表示删除旧代码。

```text
<<<< 查找
需要删除的代码
====

>>>> 替换
```

---

## 📐 替换规则

- `<<<< 查找` 下的旧代码必须与当前文件 **逐字符一致**
- 空格、缩进、空行、标点都必须保留
- 如果旧代码在文件中出现多次，自动模式会跳过，避免误改
- 多文件替换时，建议始终提供 `<<<< 文件:` 路径
- 替换内容为空表示删除该段代码
- 为了最高成功率，建议让 AI 只输出替换块，不输出解释文字

---

## 📋 推荐给 AI 的提示词

你可以把下面这段作为常用提示词发给 AI：

```text
你是一个专业的编程助手。我正在使用一个自定义的自动化代码替换工具，为了让我能一键应用你的修改，所有代码变更必须严格按以下格式输出。

## 替换块格式

<<<< 文件: path/to/file.py
<<<< 查找
[原代码，缩进和空格必须与当前文件完全一致]
====
[修改后的新代码，缩进保持一致]
>>>> 替换

## 规则

- 如果要修改多个文件，每个替换块前加上 `<<<< 文件:` 标注目标文件路径
- 如果只改当前文件，可以省略 `<<<< 文件:` 行
- 连续改同一个文件多次，每个块都需要各自的 `<<<< 文件:` 行
- `<<<< 查找` 下面的代码必须和原文件逐字符一致，包括空格、空行和缩进
- 新增代码时用附近已有代码作为定位锚点，新代码写在 `====` 下面
- 替换内容为空表示删除该段代码
- 不要输出完整文件
- 不要输出解释文字
- 只输出可以直接应用的局部替换块
- 请将最终结果包裹在 Markdown 代码块中
- 请优先编写稳定、可维护、可调试、带兜底策略的代码

如果你不确定某个文件的内容，请直接要求我发送相关文件。
```

## 👂 自动监听模式

点击顶部：

```text
📋 自动监听：开
```

开启后：

1. 去 AI 聊天窗口复制回复
2. 工具检测剪贴板变化
3. 如果内容是有效替换块，会自动解析
4. 若旧代码唯一命中，则自动应用
5. 成功后自动保存文件

为了避免误改，以下情况不会自动应用：

- 替换块格式不完整
- 当前没有打开文件
- 指定文件不存在
- 旧代码未命中
- 旧代码命中多处
- 内容已经应用过
- 内容已被判定为无效并跳过

失败时可以点击：

```text
复制反馈给 AI
```

工具会自动生成包含失败原因、原始替换内容和当前完整代码的反馈文本。

## ❓ 常见问题

### 为什么不用 AI Coding Agent？

AI Agent 很强，但它们通常更贵、更慢，也更黑箱。

对于很多代码修改任务，尤其是本地文件编辑任务，只要给对话式 AI 足够上下文，它就能直接生成高质量修改。  
本工具再通过精确匹配把这些修改安全地应用到本地文件，而不是让 AI 直接获得文件写入权限。

这通常意味着：

- 更少 token 消耗
- 更低 API 成本
- 更快完成修改
- 修改内容更透明
- 更少不必要的文件操作风险

---

### 替换失败：旧代码未命中

通常说明 AI 参考的代码和你当前文件不一致。

解决方式：

1. 点击 **复制反馈给 AI**
2. 将反馈内容粘贴给 AI
3. 让 AI 基于当前完整代码重新生成替换块

---

### 替换失败：命中多处

说明 `<<<< 查找` 下面的旧代码太短或太通用。

解决方式：

- 让 AI 加入更多上下文
- 确保旧代码只在目标文件中出现一次

---

### 替换失败：格式不完整

请检查 AI 输出是否包含：

```text
<<<< 查找
====
>>>> 替换
```

多文件修改时还应包含：

```text
<<<< 文件: path/to/file.py
```

---

### 自动监听没有反应

可以检查：

- 是否已开启自动监听
- 当前是否打开了文件
- 剪贴板内容是否真的发生变化
- AI 输出是否为完整替换块
- 内容是否已经被应用或跳过

---

### 文件被外部编辑器修改后没有更新

可以尝试：

- 切换标签页
- 手动重新打开文件
- 检查文件是否被其他程序锁定

## 🧱 设计原则

本项目的核心设计目标是：

- **稳定优先**：宁可跳过，也不误改
- **人控 AI 工作流**：AI 只负责给出明确修改，人决定何时应用
- **成本优先**：减少无意义 token 消耗和 Agent 多轮循环
- **可反馈**：失败后能快速把上下文交还给 AI
- **低心智负担**：尽量减少手动查找、复制、替换
- **本地优先**：文件处理和版本备份都在本地完成
- **可维护**：UI、业务逻辑、替换引擎尽量分层

---

## 🛠️ 开发建议

如果你要继续扩展项目，建议保持以下边界：

- `core/`：只放纯逻辑，不依赖 Qt
- `ui/`：只放通用 UI 控件
- `app/`：负责业务流程、窗口组装、状态同步
- `app/locales/`：只放语言包，不写业务逻辑

新增功能时，建议同时考虑：

- 是否需要操作日志
- 是否需要国际化 key
- 是否需要失败兜底
- 是否会影响自动监听安全性
- 是否需要保存到 `settings.json`
